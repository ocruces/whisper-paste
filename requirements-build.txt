# Frozen dependency set for the portable ZIP build (scripts\build.ps1).
#
# This is NOT the source dependency declaration. pyproject.toml lists what a
# source install needs, unpinned, so a developer gets current versions. This file is the exact
# transitive closure that was measured to produce a working frozen build, so a
# ZIP rebuilt in six months is the same ZIP.
#
# BUILD_PYTHON = 3.11
# (on its own line, in that exact form, so scripts\build.ps1 can grep it out
# rather than hard-coding the interpreter version in two places. Verified on
# 3.11.4. PyInstaller bundles the interpreter it was run with, so building on a
# different minor version silently ships a different Python to every user.)
#
# How this file was generated:
#
#   py -3.11 -m venv .venv-pin
#   .venv-pin\Scripts\pip install -e . pyinstaller
#   .venv-pin\Scripts\pip freeze          # dependency closure
#   .venv-pin\Scripts\python -c "import importlib.metadata as m; print('setuptools==' + m.version('setuptools'))"
#                                         # append this pin too: Python 3.11
#                                         # seeds it; audit scans the full venv
#
# That produces the pin set (name==version) below. The --hash lines are a
# separate pass over that exact set, run outside the repo so nothing untracked
# lands in the worktree:
#
#   py -3.11 -m pip download -r requirements-build.txt -d <tmpdir> --only-binary :all:
#   py -3.11 -m pip hash <tmpdir>\*.whl
#
# and pasted in one --hash=sha256:... line per package, in the standard pip
# continuation form. Regenerating means redoing both passes end to end and
# replacing the whole list. Do not bump a single line by hand: these are
# transitive pins, so raising e.g. faster-whisper without re-resolving leaves
# tokenizers/ctranslate2/av at versions its new metadata never asked for, and
# the set drifts out of the combination that was actually tested - and a
# hand-edited version with a stale hash would just fail closed at install time
# instead of drifting silently, which is the point of adding hashes at all.
#
# Why hashes: `==` pins a version string, not bytes. A compromised or
# re-uploaded index could serve a different wheel under the same name and
# version, and BUILD-INFO.txt's SHA-256 of this file would not notice - it
# hashes the requirements *list*, not the resolved wheels. `--hash` pins the
# exact wheel content pip installs, and pip's hash-checking mode (see
# scripts\build.ps1) refuses to install anything that doesn't match.
#
# Binding by content instead of just by version has a cost: a hash is tied to
# one specific wheel file, so this file is now Python-minor and platform
# specific in a way a bare version pin was not - which is exactly what the
# BUILD_PYTHON = 3.11 marker above already asserts for the interpreter, and
# --only-binary :all: / win_amd64 already assert for the platform. Building
# with a different Python minor needs a full regeneration, not just a new
# venv.
#
# pywhispercpp is deliberately absent. --gpu needs it rebuilt locally with
# GGML_VULKAN=1 (the PyPI wheel is CPU-only), which cannot be shipped as a
# prebuilt binary, so --gpu is a source-install-only feature and the portable
# build rejects the flag outright. packaging\whisper-paste.spec also names it in
# `excludes`; both are on purpose, see the comment there.
#
# --only-binary :all: is used at install time: a source distribution slipping in
# would build against whatever compiler this machine happens to have, which is
# the opposite of a reproducible input.
